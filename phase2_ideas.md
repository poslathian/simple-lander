1) refactor DiffusionController into KTODiffusionController
- Rather than have lunar lander create a guidance trajectory for a diffusioncontroller, where both the guidance is a position spline + pd and diffusioncontroller is a position spline + pd, lets just have one PD controller by applying the guidance margin clamp directly to model's output bspline - which is a complete q(t) trajectory, with KTOs guidance and have PD track the result. So there will now have to be for KTODiffusionController a "warm_start(waypoint,action_horizon,initial q,q')" which solves for the an initial plan with KTO to act as the guidance spline. Then also we can call inference(obs) which causes the model to diffuse a new bspline using class state variables for waypoint,action_horizon,previous q, etc (we can set q_prev to 0 on the first pass). We use the same lsq technique from our position spline/thrust spline utility to merge the two splines (which have different time references!) We would call this at target_frequency, which we should default to 3hz. Then we call get_action(obs,margin) which will return the output of the PD tracking and update the time index for the KTO guidance spline.
